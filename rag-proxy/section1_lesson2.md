## Power Save Mode

Одна из интересных кнопок в данной вкладке это **Power Save Mode**. Эта функция выключает:

- Фоновая индексация кода (analyzers, code inspections)
- Подсветка синтаксиса и ошибок (code highlighting)
- Автокомплит (code completion)
- Анализатор кода в реальном времени
- Lint-проверки

Это облегчает нагрузку на CPU и RAM, но делает IDE гораздо менее "умной".

### Когда использовать:

- Когда у тебя мало заряда на ноутбуке
- Если Android Studio тормозит и нужно временно ускорить интерфейс
- При работе над текстами, а не кодом
- Когда не нужны фичи типа автодополнения и подсказок

Соответственно, если необходимо сэкономить ресурсы (например, на ноутбуке с батареей) или просто отключить "тяжёлые" функции IDE, то тебе точно нужно включить этот функционал.

> ☼ **Совет:** Этот режим можно использовать во время проведения собеседований, чтоб кандидату было привычно работать в знакомой среде, но при этом автокомплита нет, подсветки синтаксиса нет, все как в многочисленных онлайн-блокнотах, но нагрузки на психику существенно меньше и задачи можно давать более разнообразные и глубокие (дерево проекта у нас по-прежнему на месте).

## Print

Опция предназначена для печати текущего открытого в редакторе файла, выделенного текста в текущем открытом в редакторе файле или всех файлов в указанной директории.

Как и в любом редакторе печати здесь можно задать отступы, показать/скрыть границы, задать ориентацию печати и проч. Помимо этого можно задать тип и размер шрифта, отступы и стратегию переноса строк (последнее во вкладке Advanced).

![111](/images/android-studio/part_1_lesson_2_image_1.png)

Однако особый интерес представляет вкладка «Header and Footer»,

![111](/images/android-studio/part_1_lesson_2_image_2.png)

в которой можно задать непонятные `$FILE$`, `$PAGE$` и `$TOTALPAGES$`. На самом деле, это - предопределённые переменные шаблона, которые при печати (или предварительном просмотре) подставляются автоматически.

Ниже приведен полный список этих переменных, доступных для режима печати:

| Переменная | Значение |
|------------|----------|
| `$FILE$` | Имя текущего файла |
| `$PAGE$` | Номер текущей страницы |
| `$TOTALPAGES$` | Общее количество страниц |
| `$DATE$` | Текущая дата |
| `$TIME$` | Текущее время |

## Export

Тут есть две опции:
- **Files or Selection to HTML…**
- **Export to Zip File…**

Первая опция предназначена для конвертации в HTML текущего открытого в редакторе файла, выделенного текста в текущем открытом в редакторе файле или всех файлов в указанной директории и, кроме того, сохраняет подсветку синтаксиса и форматирование (отступы, цвета и т. д.).

### Когда использовать "Files or Selection to HTML…":

- Когда нужно вставить код в статью/блог с подсветкой
- Когда нельзя использовать внешний хостинг (например, Pastebin)
- Когда нужна офлайн-вставка (например, в письмо)

### Что делает "Export to Zip File…"?

Архивирует весь проект в Zip-файл. Точка.

## Invalidate Caches…

Используется для очистки кэшей IDE и перезапуска среды разработки. Это полезный инструмент для устранения сбоев, багов и нестабильного поведения Android Studio.

![Print](/images/android-studio/part_1_lesson_2_image_3.png)

Обычно разработчики производят выполнение инвалидации с целью «починить» студию. Но что на самом деле скрывается за механизмом инвалидации и очистки кэшей? Попробуем разобраться. На экране помимо большой синей кнопки **Invalidate and Restart** мы видим 3 чекбокса и кнопку сомнительного назначения «Just restart» в левом нижнем углу окна.

### Подробное объяснение каждого из трёх чекбоксов:

#### Clear file system cache and Local History

**Что делает:**
- Очищает кэш файловой системы, в котором Android Studio хранит информацию о структуре каталогов и файлах проекта.
- Также удаляет Local History — встроенную функцию IDE, которая сохраняет локальные изменения файлов (без использования Git).

**Зачем это нужно:**
- Если IDE не видит новые/удалённые файлы;
- Если возникают ошибки при открытии/сохранении файлов;
- При повреждении или устаревании кэша, из-за чего IDE ведёт себя некорректно;
- Когда Local History занимает слишком много места.

**Последствия:**
- Local History будет утерян, восстановить его нельзя.
- После перезапуска IDE заново просканирует файловую систему проекта.

**Практическое применение:**
- Добавленные вне студии файлы. **Unresolved reference: AddedClass**. Причина: иногда индексация добавленных файлов вне интерфейса студии может не выполниться.
- **Unresolved reference: R** (sync project, rebuild project не помогают). Причина: Повреждён или устарел кэш файловой системы и индексации ресурсов Android

#### Clear VCS Log caches and indexes

**Что делает:**
- Удаляет кэшированные данные системы контроля версий (VCS — Version Control System): Git, Mercurial и т. д.
- Конкретно: история коммитов, граф изменений, отображение веток и т.п.

**Зачем это нужно:**
- Если история коммитов отображается некорректно;
- Если IDE зависает на загрузке логов Git;
- Если некорректно работает вкладка "Git" или "Version Control".

**Последствия:**
- Придётся заново загрузить и проиндексировать историю изменений репозитория;
- Это может занять время при больших проектах, но данные не теряются — только временные индексы удаляются.

**Особенности:**
- Не затрагивает твой Git-репозиторий — удаляется только индекс IDE;
- Не нужно бояться потерять коммиты — это просто внутренний кэш логов;
- Иногда стоит также очистить `.idea/vcs.xml` если проблема повторяется.

**Практическое применение:**

Ты работаешь в Android Studio с монорепозиторием (например, несколько модулей + большая история коммитов), и вдруг открываешь вкладку Version Control → Log, и IDE:
- подвисает или полностью замирает на 5–10 секунд;
- отображает только часть истории (например, до 1 месяца назад);
- не показывает коммиты по фильтрам/веткам;

**Причина:**
Кэш логов Git (VCS Log) повреждён или стал слишком тяжёлым;

Особенно часто это случается:
- после резкого переключения между ветками;
- если история слишком большая (10000+ коммитов);
- если используются подмодули или git worktrees;
- после операций git rebase, reset --hard, filter-branch и т. п.

#### Delete embedded browser engine cache and cookies

**Что делает:**
- Очищает кэш и cookies встроенного браузера, который используется для отображения HTML-контента внутри IDE.

**Где используется:**
- Авторизация в Google Firebase;
- Просмотр документации;
- Встроенные браузеры/виджеты в плагинах (например, при логине через WebView);
- Использование WebView внутри IDE UI (например, Jetpack Compose Preview с HTML).

**Зачем это нужно:**
- При ошибках авторизации в сервисах (Google, Firebase и т.д.);
- Если страница встраиваемого браузера не загружается или отображается некорректно;
- При смене аккаунта.

**Последствия:**
- Сбросятся все авторизации, cookies, временные файлы;
- Придётся снова авторизоваться в сервисах.

**Практическое применение:**

При работе, например, с Firebase Assistant (будет рассмотрен в следующих главах) могут случаться следующие ошибки:
- `This browser or app may not be secure. Try using a different browser.`
- Зависает окно авторизации на белом фоне

Казалось бы, а где вообще используется встроенный браузер в IDE и зачем он вообще нужен? Встроенный браузер нужен не для серфинга, а как часть интерактивного интерфейса IDE. Он встроен на базе JCEF (JetBrains Chromium Embedded Framework) и выполняет специальные функции, недоступные обычному десктопному браузеру, такие как:

1. **Авторизация через OAuth в Google/Firebase**
   Встроенный браузер используется для
   - входа в Google-аккаунт прямо из IDE;
   - подключения Firebase к проекту;
   - доступа к Play Console, App Distribution, Google Cloud.
   
   Пример: при нажатии "Connect to Firebase", IDE открывает окно авторизации через встроенный WebView, чтобы получить access-token

2. **Интеграция HTML/JS-интерфейсов внутри плагинов**
   Многие JetBrains/сторонние плагины используют встроенный браузер для:
   - отображения интерактивных UI на HTML/JavaScript;
   - визуальных конфигураций;
   - маркетплейсов, окон логина, аналитики и т.д.
   
   Примеры:
   - Codota / Tabnine — AI-код-помощники с Web-интерфейсом.
   - JetBrains Marketplace, если залогинен через GitHub/Google.
   - Ktor plugin — визуальная настройка backend.

3. **Визуальные HTML-документы внутри IDE**
   - Документация, встроенная справка, live previews;
   - Используется для "Help" окон, markdown preview и т.д.

4. **Firebase Assistant и прочие ассистенты**
   - Они на самом деле являются веб-приложениями, встроенными в IDE;
   - Firebase Assistant, Google Services Assistant, App Quality Insights и т.д. — рендерятся через встроенный браузер.

5. **Внутренние UI-компоненты JetBrains**
   - Некоторые части интерфейса (например, элементы Wizard'ов, логины, welcome-экраны) на самом деле — web-интерфейс в обёртке Swing.

| Место использования | Примеры |
|---------------------|---------|
| Firebase Assistant | Авторизация в Google |
| OAuth-авторизация для Google Cloud / Play Console | Плагины, CI/CD, App Distribution |
| WebView внутри некоторых плагинов | Например, JetBrains Toolbox, Login в Codota/Tabnine |
| Просмотр встроенной документации (HTML) | Некоторые справочные панели Jetpack, Compose |
| Marketplace (JetBrains Plugins) | Если требуется логин через Google/GitHub |

Таким образом, **Delete embedded browser engine cache and cookies** необходим, когда нужно очистить кэш и cookies встроенного браузера.

### Кнопка Just restart

Ее назначение банально — просто перезапуск Android Studio (закрыть программу и открыть ее).

### Заключение

Подводя итог, опишем кратко ситуации в каких случаях какой чекбокс или операция нам могут быть полезны:

| Ситуация | Что нажимать |
|----------|--------------|
| 1. IDE зависла или визуально "глючит" (UI не реагирует, вкладки не открываются) | Just Restart |
| 2. Установлен или обновлён плагин | Just Restart |
| 3. Поменяли JDK для Android Studio | Just Restart |
| 4. Переключили тему/интерфейс IDE, но не применились изменения | Just Restart |
| 5. Автодополнение не работает (Ctrl+Space ничего не предлагает) | Invalidate and Restart (без чекбоксов или с File system cache) |
| 6. Ошибка Unresolved reference: R без видимой причины | Invalidate and Restart (с Clear file system cache) |
| 7. XML-ресурсы (layout, string) не распознаются | Invalidate and Restart (с Clear file system cache) |
| 8. Файлы, добавленные вручную (в проводнике или Git), не видны в проекте | Invalidate and Restart (с Clear file system cache) |
| 9. Вкладка Git Log зависает или показывает неполную историю | Invalidate and Restart (с Clear VCS log caches) |
| 10. Git-фильтры по коммитам не работают, коммиты не отображаются | Invalidate and Restart (с Clear VCS log caches) |
| 11. Firebase Assistant не открывает окно логина / белый экран | Invalidate and Restart (с Delete embedded browser cache) |
| 12. Ошибка This browser is not secure при логине в Google через IDE | Invalidate and Restart (с Delete embedded browser cache) |
| 13. IDE после git rebase/reset показывает устаревшие/битые индексы | Invalidate and Restart (с Clear file system cache и VCS) |
| 14. Локальные изменения не отслеживаются, хотя файлы менялись | Invalidate and Restart (с Clear file system cache) |
| 15. IDE резко начала тормозить без видимой причины | Invalidate and Restart (все чекбоксы) |

Это инструмент быстрого восстановления работоспособности Android Studio без переустановки.

| Что | Объяснение |
|-----|------------|

## Local History

Локальная история (проекта) - это своеобразная система контроля версий на борту IDE. Полезность данной фичи сложно переоценить, тк лично меня она спасала не раз, особенно при проблемах с гитом, с ошибками при решении merge-конфликтов, при проблемах с обычным человеческим фактором.

Данная вкладка содержит все что касается локальной истории проекта. Здесь представлены опции для просмотра локальной истории файла, выделенного текста, всего проекта, а также неожиданная фича как создание именной точки сохранения проекта (**Put label…**).

Если проводить аналогию с компьютерными играми, то это буквально именованное сохранение прогресса игры, и если дальше что-то пойдет не так, всегда можно загрузиться с определенного момента.

Студия имеет встроенный механизм автосохранения, который покрывает 5 дней изменений, после которых история автоматически очищается и вот тут именованная точка придется как нельзя кстати: помеченные снэпшоты проекта из локальной истории не удаляются.

### ⚠️ ВАЖНО!

1. Вспоминаем раздел **Invalidate Caches…** и очень внимательно относимся к именованным меткам - они в процессе очистки при выбранной галочке очистки локальной истории будут удалены

2. Снэпшот привязывается не к какой-то конкретной ветке Git, а к конкретному временнОму состоянию проекта.

## File Properties

Это контекстное меню для конкретного файла, которое позволяет быстро просмотреть и изменить основные свойства текущего файла.

| Опция | Назначение |
|-------|------------|
| Line Separators | Настраивает символ переноса строк (LF, CRLF, CR) — важно для совместимости между ОС |
| File Encoding | Указывает кодировку файла (например, UTF-8, Windows-1251) |
| Make File Read-only / Writable | Переключает режим "только для чтения" |
| Associate with File Type... | Изменяет расширение файла |
| Add/Remove BOM | Вставляет или удаляет спецсимвол в начале файла, который указывает кодировку текста |
