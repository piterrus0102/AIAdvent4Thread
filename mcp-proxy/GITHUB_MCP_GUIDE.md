# GitHub MCP Integration Guide

## 📚 Терминология MCP (важно понимать!)

### MCP Server - это КОД (программа)
**MCP Server** = программа которая предоставляет инструменты (tools)

**Примеры MCP Server:**
- `MCPServer.js` - локальный MCP сервер (JavaScript код)
- `github-mcp-server` - GitHub MCP сервер (Go binary)

**Аналогия в Android:** `Repository` - класс который предоставляет методы

### Tool (Инструмент) - это ФУНКЦИЯ
**Tool** = метод/функция которую можно вызвать

**Примеры инструментов:**
- `get_message_count()` - получить счетчик сообщений
- `github_search_repositories()` - найти репозитории на GitHub

**Аналогия в Android:** публичные методы в `Repository`

### Данные - это ФАЙЛЫ
**Данные** = файлы которые читает MCP Server

**Примеры данных:**
- `count.json` - файл с счетчиками (НЕ MCP Server!)
- `app_data.db` - база данных SQLite

**Аналогия в Android:** `SharedPreferences`, `Room Database` - данные, не Repository!

---

## Обзор

Сервер теперь поддерживает два режима работы MCP:
1. **Локальный MCP** - работа с локальными инструментами (счетчики моделей и т.д.)
2. **GitHub MCP** - работа с GitHub репозиториями через MCP Server

## База данных

Создана SQLite БД (`app_data.db`) со следующими таблицами:

### Таблица `messages`
Хранит все сообщения из приложения:
- `id` - автоинкремент ID
- `message_id` - уникальный ID сообщения
- `text` - текст сообщения
- `is_user` - флаг пользовательского сообщения
- `timestamp` - время создания
- `model_name` - имя модели (если применимо)
- `tool_used` - использованный инструмент
- `screen_type` - тип экрана

### Таблица `model_counters`
Счетчики сообщений для моделей:
- `model_name` - имя модели (primary key)
- `message_count` - количество сообщений
- `last_updated` - время последнего обновления

### ℹ️ GitHub данные сохраняются в `messages`

**Отдельные таблицы для GitHub НЕ нужны!**

Все ответы от GitHub инструментов автоматически сохраняются в таблицу `messages`:
```sql
INSERT INTO messages (text, tool_used, tool_result)
VALUES ('Вот PR комментарии: ...', 'github_list_pr_comments', '5 comments')
```

**Почему не нужны отдельные таблицы:**
- ✅ Таблица `messages` уже сохраняет всё между сессиями
- ✅ GitHub API достаточно быстрый
- ✅ Не нужно создавать 40 таблиц для 40 инструментов
