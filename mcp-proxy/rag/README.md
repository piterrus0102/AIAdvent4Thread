# RAG (Retrieval-Augmented Generation) для курса Android Studio

Это полноценная RAG система для векторного поиска по курсу "Android Studio для непрограммистов" с использованием Ollama.

## Что такое RAG?

**RAG** (Retrieval-Augmented Generation) - это техника, которая комбинирует:
1. **Векторный поиск** - находит релевантные документы по смыслу
2. **Генерацию текста через LLM** - создает ответ на основе найденных документов

### Схема работы RAG:

```
┌─────────────────────────────────────────────────────────────┐
│ ЭТАП 1: ИНДЕКСАЦИЯ (выполняется один раз)                  │
└─────────────────────────────────────────────────────────────┘

📄 course_raw_content.md
    ↓ (разбивка на чанки)
📦 course_chunks_for_vectorization.json
    ↓ (Ollama: генерация эмбеддингов)
🗂️ vector_index.json ← ИНДЕКС СОХРАНЕН


┌─────────────────────────────────────────────────────────────┐
│ ЭТАП 2: ПОИСК (выполняется при каждом запросе)             │
└─────────────────────────────────────────────────────────────┘

❓ "Как работать с эмулятором?" ← вопрос пользователя
    ↓ (Ollama: векторизация запроса)
🔢 [0.234, -0.567, 0.891, ...] ← вектор запроса
    ↓ (косинусное сходство)
📚 Топ-3 похожих урока ← найденные документы
    ↓ (LLM: генерация ответа)
💬 "Эмулятор находится..." ← ответ пользователю
```

## Основные понятия

### 1. Чанки (chunks)
**Чанк** - это логический кусок документа. В нашем случае:
- 1 чанк = 1 урок курса
- У каждого чанка есть метаданные: название, раздел, URL

**Кто создает:** Программист (вы). Ollama здесь НЕ участвует.

**Пример чанка:**
```json
{
  "id": "lesson_1",
  "content": "Android Studio — это IDE...",
  "metadata": {
    "lesson_title": "Что такое Android Studio",
    "section": "Введение",
    "url": "/android-studio/lesson/intro"
  }
}
```

### 2. Эмбеддинги (embeddings/векторы)
**Эмбеддинг** - это числовое представление текста в виде вектора (массива чисел).

**Кто создает:** Ollama (модель эмбеддингов, например `nomic-embed-text`)

**Пример:**
```javascript
Текст: "Android Studio — это IDE"
      ↓ (Ollama)
Вектор: [0.234, -0.567, 0.891, ..., 0.123] // 768 чисел
```

**Почему это важно:**
- Похожие по смыслу тексты имеют похожие векторы
- Можно вычислить "расстояние" между текстами
- Это позволяет искать по смыслу, а не по ключевым словам

### 3. Индекс
**Индекс** - это файл (`vector_index.json`), который содержит:
- Все чанки документов
- Их векторные представления (эмбеддинги)
- Метаданные

**Что значит "сохранить индекс":**
Это просто записать JSON файл с векторами на диск, чтобы не генерировать их каждый раз заново.

**Структура индекса:**
```json
{
  "version": "1.0",
  "model": "nomic-embed-text",
  "dimension": 768,
  "created_at": "2025-11-24T...",
  "documents": [
    {
      "id": "lesson_1",
      "content": "Android Studio — это IDE...",
      "vector": [0.234, -0.567, ...],
      "metadata": {...}
    },
    ...
  ]
}
```

### 4. Косинусное сходство
Это формула для вычисления "похожести" двух векторов.

```
similarity = cos(θ) = (A · B) / (||A|| × ||B||)

Результат: от -1 до 1
  1.0 = идентичные тексты
  0.0 = нет сходства
 -1.0 = противоположные по смыслу
```

**В коде:**
```javascript
cosineSimilarity([0.5, 0.3], [0.6, 0.4])
// → 0.98 (очень похожи!)
```

## Установка и настройка

### 1. Установите Ollama

```bash
# macOS
brew install ollama

# Linux
curl -fsSL https://ollama.com/install.sh | sh

# Windows
# Скачайте с https://ollama.com/download
```

### 2. Запустите Ollama

```bash
ollama serve
```

### 3. Установите модель эмбеддингов

```bash
ollama pull nomic-embed-text
```

**Альтернативные модели:**
- `mxbai-embed-large` - более точная, но медленнее
- `all-minilm` - быстрая, но менее точная

### 4. Установите зависимости

```bash
cd mcp-proxy
npm install axios
```

## Использование

### Создание индекса (один раз)

```bash
node mcp-proxy/rag/build-index.js
```

**Что происходит:**
1. Читает чанки из `course_chunks_for_vectorization.json`
2. Для каждого чанка генерирует эмбеддинг через Ollama
3. Сохраняет индекс в `mcp-proxy/data/vector_index.json`

**Время выполнения:** ~30-60 секунд (зависит от количества чанков)

## Алгоритм RAG (пошагово)

### ФАЗА 1: Индексация (build-index.js)

```
1. Читаем чанки из JSON файла
2. Для каждого чанка:
   a) Берем текст контента
   b) Отправляем в Ollama: POST /api/embeddings
   c) Получаем вектор (массив из 768 чисел)
   d) Сохраняем: {id, content, vector, metadata}
3. Записываем всё в vector_index.json
```

**Пример запроса к Ollama:**
```javascript
POST http://localhost:11434/api/embeddings
{
  "model": "nomic-embed-text",
  "prompt": "Android Studio — это IDE..."
}

// Ответ:
{
  "embedding": [0.234, -0.567, 0.891, ...]
}
```

### ФАЗА 2: Поиск (search-cli.js / RAGService)

```
1. Пользователь вводит запрос: "Как работать с эмулятором?"

2. Векторизация запроса:
   - Отправляем запрос в Ollama
   - Получаем вектор запроса: [0.123, 0.456, ...]

3. Вычисление сходства:
   - Для каждого документа в индексе:
     similarity = cosineSimilarity(queryVector, docVector)
   - Сортируем по убыванию сходства

4. Возвращаем топ-3 документа:
   - Урок 1: релевантность 89.2%
   - Урок 2: релевантность 76.5%
   - Урок 3: релевантность 68.1%
```

### ФАЗА 3: Генерация ответа (RAGService + LLM)

```
1. Берем найденные документы (топ-3)

2. Формируем контекст для LLM:
   "РЕЛЕВАНТНЫЕ УРОКИ ИЗ КУРСА:
   
   === УРОК 1: Обзор возможностей Android Studio ===
   📱 Эмулятор Android-устройств...
   
   === УРОК 2: ... ===
   ..."

3. Создаем промпт для LLM:
   System: "Ты AI ассистент по курсу..."
   User: "<КОНТЕКСТ> + ВОПРОС ПОЛЬЗОВАТЕЛЯ"

4. Отправляем в LLM (через MainServer.callLLM)

5. Получаем ответ:
   "Эмулятор Android-устройств находится в..."
```

## Преимущества RAG

### ✅ Почему RAG лучше простого LLM?

**Без RAG (обычный LLM):**
- Модель может "галлюцинировать" (придумывать факты)
- Знания ограничены датой обучения
- Нет ссылок на источники

**С RAG:**
- ✅ Ответы основаны на реальных документах
- ✅ Можно обновлять знания без переобучения
- ✅ Есть ссылки на источники (уроки)
- ✅ Контроль над информацией

### 🎯 Когда использовать RAG?

- **Корпоративные базы знаний** - документация, политики, FAQ
- **Обучающие платформы** - курсы, учебники
- **Техническая поддержка** - мануалы, руководства
- **Юридические документы** - законы, договоры
- **Медицинская информация** - исследования, протоколы

## Частые вопросы (FAQ)

### Q: Нужно ли пересоздавать индекс при изменении курса?
**A:** Да, если изменился контент уроков. Просто запустите `build-index.js` заново.

### Q: Можно ли использовать другую модель эмбеддингов?
**A:** Да! Измените в `VectorizationClient.js`:
```javascript
const vectorClient = new VectorizationClient(
  'http://localhost:11434',
  'mxbai-embed-large' // другая модель
);
```

### Q: Почему векторный поиск лучше обычного (grep/regex)?
**A:** 
- Grep ищет по ключевым словам: "эмулятор" найдет только "эмулятор"
- Векторный поиск понимает смысл: "виртуальное устройство" найдет уроки про эмулятор

### Q: Сколько места занимает индекс?
**A:** Зависит от количества чанков:
- 1 вектор = 768 чисел × 8 байт = ~6 KB
- 4 чанка = ~24 KB (+ метаданные)
- 1000 чанков = ~6 MB

### Q: Можно ли использовать без Ollama?
**A:** Нет, Ollama необходима для генерации эмбеддингов. Но можно заменить на:
- OpenAI API (text-embedding-3-small)
- Hugging Face (sentence-transformers)
- Google Vertex AI

### Q: Почему индексация медленная?
**A:** 
- Ollama генерирует эмбеддинги последовательно
- Каждый запрос занимает ~100-500ms
- Для 100 чанков = ~10-50 секунд

**Оптимизация:** используйте более быструю модель или GPU.

### Q: Что делать если Ollama недоступна?
**A:** 
1. Проверьте запущена ли: `ollama serve`
2. Проверьте порт: `curl http://localhost:11434`
3. Проверьте модель: `ollama list`
